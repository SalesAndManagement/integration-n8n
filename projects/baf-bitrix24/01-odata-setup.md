# Етап 0, крок 1: включити OData в BAF (1С)

Це завдання для адміністратора 1С або хостера `extranet.club`. Обсяг — 20–30 хвилин.

## 1.1 Додати об'єкти до складу стандартного інтерфейсу OData

Конфігуратор → меню **Адміністрування → Склад стандартного інтерфейсу OData** (рос. «Состав стандартного интерфейса OData»).
Це налаштування зберігається в інформаційній базі й **не вимагає зняття з підтримки** та зміни конфігурації.

Відмітити (назви можуть відрізнятися — брати те, що реально є в BAF):

- Довідники: `Номенклатура`, `ХарактеристикиНоменклатури` (варіанти: розмір/колір), `ОдиниціВиміру` (`УпаковкиОдиниціВиміру`), `Склади`, `ВидиЦін`, `Штрихкоди`, групи/види номенклатури
- Регістр накопичення залишків товарів — точну назву покаже розвідка (`ЗапасиНаСкладах`, `ТовариНаСкладах` або аналог), з віртуальними таблицями `Balance`
- Регістр накопичення резервів / замовлень покупців — якщо будемо віднімати резерви
- Регістр відомостей `ЦіниНоменклатури` — якщо синхронізуємо ціни

Краще додати з запасом: зайве в OData просто не читатимемо, а от кожне доповнення потім — це ще один похід до адміна.

## 1.2 Включити публікацію OData

Варіант через конфігуратор: **Адміністрування → Публікація на веб-сервері** → вкладка «Інше» → галочка **«Публікувати стандартний інтерфейс OData»** → Опублікувати.

Те саме вручну у файлі публікації `default.vrd` — атрибут у корневому елементі `<point>`:

```xml
<point xmlns="http://v8.1c.ru/8.2/virtual-resource-system"
       base="/baf"
       ib="Srvr=&quot;...&quot;;Ref=&quot;...&quot;;"
       enableStandardOData="true">
```

Після зміни `.vrd` — перезапуск пулу веб-сервера (IIS) або `apache2`.

## 1.3 Окремий користувач для інтеграції

Створити користувача **`n8n_integration`**:

- аутентифікація 1С (логін + пароль) — OData працює по HTTP Basic, доменна/OpenID не підійде
- пароль без обмеження строку дії, без обов'язкової зміни при першому вході, без 2FA
- права: **тільки читання** перелічених вище об'єктів. Окрема роль краще за «Повні права»
- знято «Показувати в списку вибору»
- врахувати: сеанс OData споживає клієнтську ліцензію

## 1.4 Перевірка (робить адмін або ви)

```bash
# сервісний документ: список усіх опублікованих сутностей
curl -u 'n8n_integration:ПАРОЛЬ' \
  'https://vladiyan.extranet.club:46795/<base>/odata/standard.odata/?$format=json'

# перші 5 позицій номенклатури
curl -u 'n8n_integration:ПАРОЛЬ' \
  'https://vladiyan.extranet.club:46795/<base>/odata/standard.odata/Catalog_%D0%9D%D0%BE%D0%BC%D0%B5%D0%BD%D0%BA%D0%BB%D0%B0%D1%82%D1%83%D1%80%D0%B0?$top=5&$format=json'
```

`<base>` — ім'я публікації в URL (той відрізок шляху, який іде після порту при вході у веб-клієнт).

Очікуваний результат: JSON зі списком сутностей. Що означають типові помилки:

| Відповідь | Причина |
|---|---|
| `401 Unauthorized` | неправильний логін/пароль або не 1С-аутентифікація |
| `404 Not Found` | OData не включений у публікації (крок 1.2) або неправильний `<base>` |
| порожній `value` у сервісному документі | не заповнений склад інтерфейсу OData (крок 1.1) |
| `403` / «Недостатньо прав» | користувачу не видані права на читання об'єкта |

## 1.5 Що передати мені

1. Повний базовий URL OData (до `/odata/standard.odata` включно).
2. Логін/пароль користувача — **не в чат**: покласти у креденшали n8n на вашому сервері, мені достатньо підтвердження «створено, curl проходить».
3. Чи є білий список IP на боці хостера — тоді додати IP вашого сервера з n8n.
4. Вивід воркфлоу-розвідника `baf_00_discovery_odata`.
